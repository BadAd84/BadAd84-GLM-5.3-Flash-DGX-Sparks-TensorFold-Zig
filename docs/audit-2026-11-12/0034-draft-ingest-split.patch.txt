Subject: [PATCH] glm: TF_GLM_OVN_DRAFT_INGEST_SPLIT, a decode ingest's fc and k, v as each rank's columns

New here (lane DrafterLever, 2026-11-13), not from the fork or production; default off. Every rank runs DFlash2's
whole context ingest each round: fc (4,096 x 20,480 at 4 bits, 47.2 MB) and the five layers' k, v projections
(5 x 4.7 MB), the same 71 MB of weights read on all three ranks. With TF_GLM_OVN_DRAFT_INGEST_SPLIT=1, at two ranks
or more, an ingest of a decode verify's tap rows (32 or fewer) runs fc and each layer's k, v as this rank's
64-column share of their outputs (fc 1408/1344/1344 columns at TP=3, k and v 384/320/320 each), all-gathers the
shares in the drafter's partial-sums buffer (one gather for fc, one for all five k, v) and places them with strided
copies (cuMemcpy2DAsync); the hidden norm and the ring writes then run on the whole rows as before. The five k, v
matmuls share one launch of group sums, which every one of them recomputed. Prompt ingests (more rows) keep the
whole path.

Bits: the drafts are those of the whole path, by construction. A share is the whole linear's rows (quantize4 per
row, pack per 64-column tile), it starts on a 64-column tile, and it launches with the whole linear's K slices
(cuda_q4.Q4.sk read by kSlices; fc's own shape would take 8 slices where the whole takes 4), so every output column
is the same tile lane, the same K order and the same cluster sum as in the whole launch. Replies cannot move:
verification keeps the target's own sample. Knob off: nothing loads, no launch changes; Q4.sk defaults to 0, which
is splitK as before.

Why this lever (the profile, work/drafter-lever/REPORT.md): on rank 0 of the pad stack at one stream
(~/nsys/f5-pad-p1.sqlite, 152 decode rounds) the drafter step is 5.95 ms a round and its ingest 0.449 ms (fc
0.233, each k, v group_kernel 0.035); the drafter knobs (DOWN4, ONEPASS, MLPSPLIT) leave the ingest untouched, and
production's whole context update is 0.265 ms (its boot calibration). Expected: about 46 MB fewer weight bytes a
round a rank, -0.1 to -0.25 ms a round at every stream count (0.3 to 0.6% at one stream, about 0.3% at four) after
the two gathers and nine strided copies it adds, which needs the arm in both orders on this box.

+//! TF_GLM_OVN_DRAFT_INGEST_SPLIT: a decode ingest's fc and k, v projections as each rank's columns, gathered, placed.

+/// One rank's output columns of an `n`-column linear: whole 64-column tiles, the first `tiles % world` ranks one more.
+pub const Share = struct { col0: usize, n: usize };
+
+pub fn share(n: usize, world: usize, rank: usize) error{BadIngestShare}!Share {
+    if (world == 0 or rank >= world or n % 64 != 0 or n / 64 < world) return error.BadIngestShare;
+    const tiles = n / 64;
+    const base = tiles / world;
+    const extra = tiles % world;
+    return .{ .col0 = 64 * (rank * base + @min(rank, extra)), .n = 64 * (base + @intFromBool(rank < extra)) };
+}
+
+/// This rank's 4-bit shares: fc's columns, and each layer's k columns then v columns (the whole kv's stacking).
+pub const Shares = struct { fc: q4.Q4, kv: [df.LAYERS]q4.Q4 };
+
+/// `q` cut from a linear of `whole_n` columns keeps that linear's K slices, so each column sums its K as before.
+pub fn keepSlices(q: q4.Q4, whole_n: usize) q4.Q4 {
+    var s = q;
+    s.sk = q4.splitK(whole_n, q.k);
+    return s;
+}
+
+/// Whether an ingest of `rows` rows runs on the shares: two ranks or more, and a decode verify's tap rows at most.
+pub fn splits(world: usize, rows: usize) bool {
+    return world >= 2 and rows > 0 and rows <= df.STEP_ROWS;
+}
+
+/// One rank's bytes in a gather: `parts` x `rows` rows of the widest share of `n` (rank 0's), alike on every rank.
+pub fn slot(n: usize, world: usize, rows: usize, parts: usize) error{BadIngestShare}!usize {
+    return parts * rows * (try share(n, world, 0)).n * 2;
+}
+
+/// A strided copy of gathered bf16 rows into whole rows, in bytes: cuMemcpy2DAsync's offsets, pitches and extent.
+pub const Place = struct { src: usize, src_pitch: usize, dst: usize, dst_pitch: usize, width: usize, height: usize };
+
+/// fc: rank r's slot, `rows` rows of its columns, into rows `n` wide at its first column.
+pub fn placeFc(n: usize, world: usize, r: usize, rows: usize) error{BadIngestShare}!Place {
+    const s = try share(n, world, r);
+    return .{ .src = r * try slot(n, world, rows, 1), .src_pitch = s.n * 2, .dst = s.col0 * 2, .dst_pitch = n * 2, .width = s.n * 2, .height = rows };

+
+/// kv: rank r's slot, `layers` x `rows` rows of [its k columns, its v columns], into rows [k (half), v (half)].

+    v.src += s.n * 2;
+    v.dst += half * 2;

+}

+/// Host stand-in for cuMemcpy2DAsync on bf16 words (offsets and pitches in bytes, as Place holds them).
+fn copy2D(src: []const u16, dst: []u16, p: Place) void {
+    for (0..p.height) |row| {
+        const s = (p.src + row * p.src_pitch) / 2;
+        const d = (p.dst + row * p.dst_pitch) / 2;
+        @memcpy(dst[d..][0 .. p.width / 2], src[s..][0 .. p.width / 2]);

+/// A bf16 word for (layer, row, column), mixed so that a word read from the wrong place matches by chance at most.
+fn word(layer: usize, row: usize, col: usize) u16 {
+    var x: u32 = @intCast(layer << 17 | row << 12 | col);
+    x ^= x >> 16;
+    x *%= 0x7feb352d;
+    x ^= x >> 15;
+    x *%= 0x846ca68b;
+    x ^= x >> 16;
+    return @truncate(x);
+}

Subject: [PATCH] glm cuda: TF_GLM_OVN_PIECES_SIDE_GLUE, a solo pass's pieces glued and shared on the side stream as a pair's are

A prompt chunk's pieced sites (cuda_forward.zig pieced) run exchangePieces, which fills each piece on the main stream and
posts its partials exchange on the side stream, and then gluePieces, which glues every piece on the MAIN stream after the
last piece was filled and posts each piece's share on the side stream behind the exchanges still queued there. A solo pass
(the recipe's TF_GLM_CHUNK_SOLO=4096, nothing to overlap with) therefore piles every piece's glue and share after its last
fill: on a 4,096-row pass the main stream waits 18.3 us a row for the partials exchange and 24.5 for the glued rows' share,
9.3% of the pass (queue76 capture f76w, request 1, `scripts/prefill_stages.py`), where production's accounting has 5 to 12.

A paired step already schedules a site differently (cuda_forward_pair.zig exchangeGlue): each piece is filled on the main
stream, and on the side stream its exchange, its glue and its share follow in order, so piece q's glue and share run while
the main stream fills piece q + 1 and the main stream waits once, for the last piece's chain, before the next site
(awaitShared). TF_GLM_OVN_PIECES_SIDE_GLUE=1 gives a solo pass that schedule. pieced() calls pieceSite for each site:
without the switch it is exchangePieces then gluePieces, the same calls in the same order as before; with it, exchangeGlue
then awaitShared. Scheduling only: the same kernels with the same rows and arguments, the glue kernels on the side stream
and the side stream's order of collectives unchanged, so the bits are the same. The glue touches only its own piece's rows
(x, post, comb, xs and normed by row, and hcpart, which only the glue uses), and no fill reads them, so the overlap is a
row-disjoint one. Default off; with the profiler on (its spans sit on the main stream's glue) the switch is ignored.

The two method aliases exchangePieces and gluePieces on Forward are replaced by pieceSite (nothing else used them).

Host test: the switch's reading, on only with the switch and never under the profiler (cuda_pieces_side_glue_test.zig,
listed in cuda.zig's test block); the schedule is checked by the reply digests, which must equal the recipe's on every cell.
The registry row follows TF_GLM_OVN_SIDE_PRIO's and the docs line follows that switch's, so patches/pr1411's hunks still
apply on top. Not run on a GPU yet.

New here, not a re-seat: written on this series at v1.2.9.

+/// A solo pass's pieced site: glued on the main stream, or with `side` on the side stream as a pair's are.
+pub fn pieceSite(f: *const Forward, p: *const Pieces, j: usize, site: Site, cut: []const [2]usize, side: bool) !void {
+    if (!side) {
+        try pieces.exchangePieces(f, p, j, site, cut);
+        return pieces.gluePieces(f, p, j, site, cut);
+    }
+    try exchangeGlue(f, p, j, site, cut);
+    try awaitShared(f, p, cut.len);
+}

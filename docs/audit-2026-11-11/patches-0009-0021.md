All 118 worklist lines are classified by reading the hunks against `work/pin/tree` (pin), `work/parity/tree` (par) and the era tree; nothing was built or run. Paths are under `zig/src/families/glm/` unless a longer path is shown.

The one live default-path defect is in `attendLastRow`: the pin's one-row sparse attention now runs over `rows` rows. Separately, 0018 changes the knobs-off default away from the pin; that is the source commit's intent, but 0018's description is wrong about the pin.

## 2. Ranked findings

### R1. REGRESSION, default path, live in the final tree: `attendLastRow` runs sparse attention over `rows` rows instead of 1

- **Pin:** `cuda_dsa_block.zig`:209 calls `sparseAttentionFormat(..., v.partials, v.ol, 1, l.heads, l.lw, scale)`, one row. `v.qa` and `v.ol` are already offset to the last row (pin :186-187), and `selectTokensProfile` just above selected one row.
- **Parity:** par :226-230 passes `rows` to `sparseAttentionFormat` (:230), and the hook at :228 calls `onepass.takes(false, ...)` and `onepass.run(..., rows, ...)`.
- **Era:** era :244-247 uses `takes(k.set.prompt, ...)` and `1` at both calls, so parity differs from both the pin and era.
- **How it happened:** 0016 added the hook plus a second call with `rows` after the pin's one-row call. 0029's second hunk then deleted the pin's one-row line and kept the `rows` one.
- **When it bites:** every `blockLastRow`, which is `mtpMode` with `propose`, a prefill buffer and `n > 1` (`cuda_forward.zig` par :519, :543), once the context passes the dense limit (`sparseRows`). No knob, any TP.
- **Effect:**
  - The launch does `n` rows of work where the pin does 1.
  - It reads `qa` and writes `ol` for rows `[n-1, 2n-1)`, which is past the `rows`-row regions (`cuda_state.zig` par :249) whenever `2n - 1 > b.rows`. Those bytes fall into the neighbouring scratch regions of the same arena.
  - Rows 1 and up use stale token lists and counts.
  - The row actually consumed (`s.ol + off`, par :193-194) is the launch's row 0. [INFERENCE] Its value is probably unchanged; I did not run it.
  - With SPARSE_ONEPASS the hook is dead here because of the literal `false`.
- **Smallest fix:** make par :228-230 the era form: `takes(k.set.prompt, ...)`, `run(..., 1, ...)`, and `sparseAttentionFormat(..., 1, ...)` as at pin :209.

### D1. Intended default flip, not gated to the pin: 0018 `allocate_shared_drafts`

- **Pin:** `cuda_lanes.zig`:100 `.allocate_shared_drafts = drafting`, and the pin's `native/copy_drafts_cuda_test.zig`:73 asserts true.
- **Parity:** par :140 is false unless `TF_GLM_OVN_SHARED_DRAFTS` is set. 0027 states the flip is deliberate (source commit 7b41f0d26) and edits that test literal to false.
- **The discrepancy:** 0018's own description says knob-off is "the pin's behaviour today". That is false against pin :100.
- **When it bites:** knobs off, MTP on, two or more streams in a shared round (the core reads the flag at `core/lanes/engine.zig`:292 and `windows.zig`:264). It changes which shared draft rows are reserved, not token values.
- **Decision for you:** if "knobs off equals pin" is the rule, invert the knob so the default is `drafting`. Otherwise keep it and correct 0018's description.

### R2. REGRESSION, latent: `m.tiled = false` dropped from `Modules.load` (0017)

- **Pin:** `cuda_forward.zig`:88 initialises the field because `m` starts `undefined` (pin :89 comment). Era :116 keeps the line.
- **Parity:** no initialisation in `load` (par :69-115). 0019's description calls the line "later-era", which is wrong.
- **When it bites:** not today. The engine assigns `e.m.tiled = o.settings.tiled` (`cuda_engine.zig` par :200) before any `set()` call, and `glm_loader_gate.zig`:521 never reads it. Any new caller of `Modules.load` that calls `set()` without assigning it reads an undefined bool.
- **Smallest fix:** restore `m.tiled = false;` next to `m.packs = null;` (par :110).

### R3. REGRESSION, low: `m.* = undefined` dropped from `Modules.deinit` (0017)

- **Pin:** :109 poisons the struct after unload. Parity :124-134 does not; era does not either.
- **When it bites:** only on a use-after-deinit, which Debug builds would no longer catch.

### Knob-on only (default path unaffected)

- **K1, 0021, unclear until run:** `Mla.wanted()` (par `cuda_glue.zig`:149-151) omits KVB8, but `absorb_q8` and `expand_v8` sit behind `ovn` in `loadOvn` (:119-124).

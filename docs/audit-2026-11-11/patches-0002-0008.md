Paths are under `zig/src/families/glm/` unless a longer path is given. "pin", "par" and "era" mean `work/pin/tree`, `work/parity/tree` and `ai-engine/work/aie/fair-base`.

## 2. Ranked REGRESSION and unclear items

### R1. A paired prompt step with a drafter loaded returns `error.BadPair` (0007)

- **Pin:** `pairedAt` refuses any pair when `e.drafter != null` (cuda_prompt_pair.zig:63), and so does `prefill` (:77).
- **Patched tree:** a pair is allowed with a drafter when both chunks end before the last 2,048 rows (par :76-83, :92). But `e.view` sets `.taps` whenever a drafter exists (par cuda_engine.zig:291), `prefill` never clears it (par :101-106), and `pairBody` returns `error.BadPair` on `f.taps != null` (par cuda_forward_pair.zig:19, same line in the pin).
- **When it bites:** the default path with `--drafter` (serve.sh:91 default), any world of 2 or more including TP=3, pair on (default), a lone prompt of 6,144 tokens or more with no other stream decoding. Trace at start 0: `takesTwo` is true, `drafterIdle` needs 4096 <= len - 2048, `ringsAgree(0, 4096, 0, 2048)` is true. [INFERENCE] every rank returns the error and followers exit on it (`else => return err`, par cuda_follow.zig:417-420).
- **Why it was not seen:** the ledger's benches ran with `DRAFTER=0` and short prompts.
- **Smallest fix:** add `fa.taps = null; fb.taps = null;` after `fb.prof = null;` in par cuda_prompt_pair.zig:104 (era :109-110). To stay on pin behaviour instead, restore `e.drafter != null` in both conditions.

### R2. A wide step is chosen when the first chunk was cut short by a mark (0007)

- **Pin:** marks sit on the 2,048 grid, so a mark is never strictly inside a chunk; a mark at the next chunk start blocks the pair (cuda_follow.zig:231, cuda_prompt_pair.zig:42-46).
- **Patched tree:** `a_end` may be a mark inside `(start, start + 2048)`, and `wide` is still taken (par cuda_follow.zig:245-247). `n` becomes `(mark - start) + 2048`, so `prompt_pair.prefill` runs chunk a as the full 2,048 rows across the mark.
- **Consequences:**
  - The mark's keep is never called, because marks fire only at a step start (par cuda_prompt_pair.zig:94). The state the cache planned there is silently not kept.
  - If `mark - start < world`, `prefill` returns `error.BadChunk` (par :92).
  - If `mark - start < min_rows` (512), a pair runs below the floor `takesTwo` enforces (unclear whether `pairBody` is correct there; `glm_pair_tests` with a short b decides).
- **When it bites:** default path, world 2 or more, pair on, lone stream, and a mark deeper than about 4,096 rows from the end with a drafter (about 2,560 without). [INFERENCE] a long new tail after the history mark, or shared cuts in a long cold prompt.
- **Smallest fix:** `const wide = alone and a_end == start + engine.prompt_rows and (...)` (era cuda_follow.zig:273).

### R3. `q4.Kernels.module` is never set, so `loadF32` always fails (0004)

- **Pin:** has no such field.
- **Patched tree:** `load` omits `.module = group_mod` (par cuda_q4.zig:37-45; era has `.module = group`). `dflash_load.zig:198` runs `dr.wide4 = try e.m.q4.loadF32()` when `down4 and (split or sff != 0)`.
- **When it bites:** `TF_GLM_OVN_DRAFT_DOWN4=1` with `--drafter-bits 4` and either world 2, or `TF_GLM_OVN_DRAFT_MLPSPLIT > 0` at world 3 or more. That is serve.sh's `KNOBS=measured` set at `WORLD=3` (serve.sh:66). [INFERENCE] the drafter load returns `error.NoQmmGroupModule`. The `glm-draft-onepass` GPU check calls `ks.loadF32()` too (`zig/tests/cuda/glm_draft_onepass_tests.zig`:61).
- **Smallest fix:** add `.module = group_mod,` to the initialiser at par cuda_q4.zig:38-43.

### R4. The L2 prefetch fork for site `o` runs before the projections (0003)

- **Pin:** project, then fork, then chain (cuda_kda_block.zig:85-87; "Site o's place in a KDA block: between its projections and its chain", cuda_l2pf.zig:242). Era agrees.
- **Patched tree:** fork, then project (par :91-92), and the fork sits inside the `.projections` profile span.
- **When it bites:** decode windows wherever L2PF is on. L2PF is on by default on a GB10 at two or more ranks (`Options.on = true`, `want` at pin cuda_l2pf.zig:10, :47-49), so this is the default TP=3 decode path. No numeric change. [INFERENCE] performance only: the `o` weights are read into L2 while the input projection is still reading its own stack.
- **Smallest fix:** move the line back after `stamp.end()`, as pin :85-87.

### R5. `TF_GLM_CHUNK_SOLO=4096` is broken by three lines across 0003, 0004 and 0007

- **Pin:** solo excludes the pair twin (cuda_engine.zig:149), a pass over 2,048 rows takes the generic path guarded by `prompt_solo.allowed` (:358-360), and the drafter sizes `taps_prefill` for it (dflash_load.zig:168, dflash.zig:38).
- **Patched tree:**
  - the twin is created under solo (par cuda_engine.zig:170);
  - every pass over 2,048 rows goes to `prompt_pair.prefill` (par :385);
  - `tap_rows` stays 2,048 (par dflash_load.zig:197).
- **When it bites:** only with `TF_GLM_CHUNK_SOLO=4096`, which is not in serve.sh's `DEFS`.
  - World 1, or `TF_GLM_PROMPT_PAIR=0`: `e.pair == null`, so `BadChunk` on every lone wide step (par cuda_prompt_pair.zig:91).
  - With a drafter: `BadChunk` when the step reaches the last 2,048 rows, otherwise R1.
  - World 3 with a second chunk of exactly 2 rows: `rb < world`, `BadChunk`.
  - Without a drafter: a pair pass runs where the pin ran a solo pass.
  - The `tap_rows` drop is masked by the routing today. Once routing is restored, a 4,096-row tapped pass meets a 2,048-row `taps_prefill`, and `promptRun` returns `DrafterContextTooWide` (par dflash.zig:402).
- **Smallest fix (all three together):** restore `o.settings.solo` at par cuda_engine.zig:170, restore `and e.pair != null` at :385, and add `.tap_rows = df.tapRows(e.bp.rows)` to the initialiser at par dflash_load.zig:197.

### R6. The drafter checkpoint header validation and short-read checks are gone (0004)

- **Pin:** `headerSize` and `parseHeader` checks, a range check against the file size, every read length checked (dflash_load.zig:51, :113-118, :135-146), and a test.
- **Patched tree:** raw `std.json` with unchecked unwraps, and `_ = try readPositionalAll` (par :50, :151-167). Era has this older form, so the port undid upstream hardening.
- **When it bites:** default path with `--drafter`, but only on a malformed or truncated `model.safetensors`. [INFERENCE] a safety panic or undefined behaviour on a bad header; a truncated file loads stale buffer bytes as weights, which costs draft quality (verify still decides replies).
- **Smallest fix:** restore pin lines 4, 51, 112-119, 135-146 and the test at 288-312; keep the knob code after them.

### R7. `TF_GLM_PROMPT_TAIL=1` is silently a no-op (0007)

### R8. The whole-prompt pass does not cut at marks (0007)

- **Pin:** marks are on the grid, so `Engine.prefill`'s 2,048 stride lands on them.
- **Patched tree:** marks can be at any row, but `Engine.prefill` still strides 2,048 from its start (par cuda_engine.zig:360-366) and marks fire only at step starts (:394). Era passes no marks on this path (era :393-400).
- **When it bites:** `TF_GLM_PROMPT_STEPS=0` (par cuda_lanes.zig:81, :235) and any other caller of `Leader.prefill` with marks. [INFERENCE] planned states are not kept, so the next turn re-prefills.
- **Smallest fix:** in `Engine.prefill`, take `rows = chunkEnd(start, ids.len, marks.at) - start` when marks are given.

### R9. `Store.keep` lost the implicit length equality (0006)

- **Pin:** `std.mem.eql(u32, e.tokens, prompt[0..n])` requires `e.tokens.len == n` (zig/src/core/prompt_cache.zig:463).
- **Patched tree:** `prefix.starts(prompt, e.tokens)` accepts any prefix length (par :466). Era has the explicit `e.tokens.len == n` (era :470).

Entries made by `keep` satisfy it (par :507); a learned or disk state written under another lookahead would not, and `keep` would then report "the same state again" and skip the save. Independent of the knob.
- **Smallest fix:** add `e.tokens.len == n and` before `prefix.starts` at par :466.

### Unclear

- **U1. Any-row keeps against the pin's stated invariant (0007, intended).** The pin says "Prompt kernels change arithmetic with a chunk's rows: states keep and resume only on chunk starts" (cuda_native.zig:27). The era says a prompt row's bits do not depend on its chunk. By reading:
  - `glm_mm` prompt launches are row-count invariant by default (pin cuda_mm.zig:100-110, `one` gives `sk = 1`);
  - the KDA chain switches kernels at 64 rows (pin cuda_kda_block.zig chainRows, `rows >= kda.wide_rows`);
  - `wideSelect` switches at 64 rows (pin cuda_sparse.zig:26).
  
  Whether those pairs are bit-equal cannot be decided by reading. What decides it: the patch's own `glm-resume-check <ckpt> <rank> <world> <idfile>` at TP=3 on the parity image with the serve's settings (its cases include 1-row and 62-row chunks).
- **U2. Pairs now run with a drafter loaded (0007, intended, once R1 is fixed).** The pin never ran this. What decides it: a pair check with `--drafter` comparing against chunk-at-a-time output.
- **U3. Tail pieces under `TF_GLM_INDEX_CUDA=1` use a different launch geometry (0005).** `takes` is asked for the chunk's rows, but `scores` is called per piece (pin cuda_sparse.zig:100-102). A last piece under 64 rows of a chunk of 64 or more now runs `loop = 1` and `grid.y = nb`, where the pin ran `loop = 16`. Bits are the same by the kernel (`first = blockIdx.y * loop`, pin `zig/kernels/cuda/glm_index_scores.cuh`:83). Speed is undetermined; an A/B at `INDEX_CUDA=1` on a prompt whose last chunk has `rows mod 512` in 1..63 decides. Era has the same form.

The remaining candidates, in the order I would test them:

1. **The module the handle came from is the wrong one.** The check does `cuda.Module.load(gpu.d, cuda.kernels.glm_glue)` and
   `glm.glue.Kernels.load(glue_mod)`. If patch 0012/0034 put `tf_glm_select_rows` into a DIFFERENT module than
   `cuda.kernels.glm_glue` resolves to, `m.function(...)` would succeed against a module that the driver no longer has the
   kernel in, or the launch uses a context that has the module loaded twice.
2. **Two modules define `tf_glm_select_rows`** (ours and upstream's glue), so the handle resolves to the wrong one.
3. **The device context the check uses** differs from the one the module was loaded on (channel vs stream).

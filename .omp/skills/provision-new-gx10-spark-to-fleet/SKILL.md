Use when a new GB10 Spark is added to the OTS fleet and needs baseline provisioning (reachable via YubiKey, hostname set, passwordless pam_rssh sudo, adam in the docker group). Full detail lives in ots-infra `docs/NEW-SPARK-SETUP.md`. This is baseline only - kindling spark-os, a serve, and fabric cabling are separate role decisions. Last run: spark6, 2026-10-08.

## Facts
- Fleet Sparks are **ASUS Ascent GX10** (GB10, aarch64/sm_121, ~121 GiB UMA on stock DGX OS, 916 GB NVMe), ship **stock DGX OS** (Ubuntu 24.04.5, kernel `7.0.0-1019-nvidia`, driver 580.178.04 on spark6), timezone already Europe/London. LAN NIC = Realtek 10GbE, OUI **`a0:ad:9f:dc:*`** (spark5's is `30:c5:99`), linked at **1 Gb/s** on the office switch (spark4 and spark6 measured). WiFi = MediaTek (down).
- Names `sparkN.ots-int.net` -> `192.168.99.1N` (spark1 `.11` ... spark6 `.16`; next spark7 `.17`). The owner adds the UniFi reservation and the DNS record. YubiKey agent: `export SSH_AUTH_SOCK=C:/Users/Adam/AppData/Local/gnupg/agent-gui/S.gpg-agent.ssh.cyg`; connect `ssh -A adam@...`.
- Reference box for the pam_rssh files: **spark4** (stock DGX OS like a new box; module = spark1's build, sha256 `85f63861...`, 857,088 bytes).

## Procedure
1. **Find it**: new box = DHCP, may transiently appear on another VLAN during OOBE. From the Proxmox host (192.168.99.100, has nmap): ping-sweep `192.168.99.0/24` then `ip neigh show | grep -i a0:ad:9f`. An `ssh-keyscan` answering on the expected IP but no DNS name yet = the owner still has to add the record.
2. **Owner's one password step, as a FILE**: build `work\sparkN-setup.txt` from `ssh-add -L` (never retype the key) holding ONE command line (template in `NEW-SPARK-SETUP.md` section 2): installs the key with the perms sshd needs (`chmod go-w ~`, 700 `.ssh`, 600 `authorized_keys`, checks the key BODY so a mangled earlier paste does not count) and the temp NOPASSWD rule `/etc/sudoers.d/90-adam-temp` via `visudo -cf` + `install`. One line because anything pasted after a `sudo` is read as its password; a file because copying a long command out of a terminal adds line breaks (owner, 2026-10-08). Test it in a fake HOME with `sudo` stubbed before handing it over. Never ask for or handle the password.
   - spark6 measured: the owner's first manual key install was refused for adam, root and every fleet key until this line ran. Diagnose a refusal with `ssh -v` (which keys are offered) and by trying the fleet's other keys from spark1 / the Proxmox host, then hand over the file - do not guess usernames.
3. **Audit** (`ssh -A`): hostname, `uname -m`, `nvidia-smi`, `free -g`, `df -h /`, `timedatectl`, `ip -br addr`, link speed, `lspci | grep -c 15b3` (0 = not cabled), `/etc/sudoers.d`, `/etc/pam.d/sudo`, `id -nG`.
4. **Baseline in one script** (spark6's: `work/spark6/spark6_baseline.sh`, run with `ssh -A` while the temp rule exists): `hostnamectl` + `/etc/hosts` `127.0.1.1 sparkN` (DGX OS had none); `usermod -aG docker adam` FIRST (it is also the way back if sudo is ever lost); the four pam_rssh pieces with `install -m/-o/-g`: the module (644), `/etc/security/sudo_authorized_keys` (600, = `ssh-add -L`, 743 bytes), `/etc/sudoers.d/ssh-agent-auth` (440, `Defaults env_keep += "SSH_AUTH_SOCK"`, MANDATORY, `visudo -cf` first), and the PAM line `auth       sufficient libpam_rssh.so auth_key_file=/etc/security/sudo_authorized_keys` inserted before `@include common-auth` after a backup (`sudo.bak-rssh`), under a root safety net (a `setsid nohup sh` sleeper that writes `/run/pamsafe.pid`, then restores the backup after 120 s), disarmed by `kill $(cat /run/pamsafe.pid)` once `sudo true` still works after the edit.
5. **Drop the temp under a net, verify from a NEW session** (`work/spark6/spark6_switch.sh drop|verify`): keep a copy in `/root`, start a root sleeper (`/run/tempsafe.pid`) that puts the temp back after 150 s, remove the temp; then in a new `ssh -A` session `sudo -k; sudo -n true` must FAIL and `sudo -k; sudo true </dev/null` must SUCCEED; then kill the sleeper by PID and delete the kept copy.
6. **Record**: `~/INVENTORY.md` on the box (teardown manifest, fleet rule), the host table in ots-infra `docs/INFRA-LAYOUT.md`, ots-infra `AGENTS.md`, the global `~/.omp/agent/AGENTS.md` fleet facts (then the single-file omp-config backup, signed), and refresh this skill's facts.

## Traps (each cost real time)
- **`sudo -n` NEVER works under pam_rssh** - it refuses the agent probe ("a password is required"). Automation uses `sudo <cmd> </dev/null` + `ssh -A`, never `sudo -n`. A `sudo -n grep ...` returning empty is a FAILED sudo, not an absent config.
- **Disarm a safety net by killing its PID, never with a marker file.** spark6 (2026-10-08): my verify step's cleanup deleted the PAM net's "cancel" marker 25 s before the net fired; that re-armed it, and it restored the pre-rssh `/etc/pam.d/sudo` after the temp rule was already gone - sudo locked to the owner's password. Recovered without the owner through adam's docker group: build the intended file in `/tmp/fix`, then `docker run --rm --network none -v /etc/pam.d:/p -v /tmp/fix:/f:ro busybox sh -c 'cat /f/sudo > /p/sudo'` (rewrites in place, root:root 644 kept; `work/spark6/spark6_pamfix.sh`), remove the image after. Killing a waiting `sh -c '...; sleep N; restore'` by PID was tested on spark6: the restore never runs.
- **ConnectX** absent from `lspci` = not cabled (expected on a fresh box) -> cannot join a TP RoCE ring until cabled. Stock DGX OS shows ~121 GiB (vs ~123 on kindling spark-os, which reclaims the ~2 GiB display carveout via dispramd).
- Keep the new box out of the TP=3 serve docs' "what runs" tables until it has a role; mark it OFF the ring in the fleet facts.
